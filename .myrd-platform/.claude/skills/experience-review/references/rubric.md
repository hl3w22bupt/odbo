# 五维 rubric（1 / 3 / 5 锚点）

> 本文件是审美官的内部评分标准（盲评纪律：不进入游戏开发 agent 的任何上下文）。
> 分数是 **advisory 评分**，不是合格判定——它服务于「告诉人哪里最值得改」与后续金标校准。

## 1. palette —— 配色与风格一致性

有 style card / 用户拍板 artStyle 时，**一致性是硬口径**（偏离声明方向是 finding，不是品味分歧）。

| 分 | 锚点 |
|---|---|
| 1 | 色彩冲突刺眼（大面积互补色对撞/饱和度拉满）；或与声明的风格方向完全不符 |
| 3 | 有基本色板但平淡/单薄；个别颜色跳出整体氛围；对比度勉强可读 |
| 5 | 色板统一且服务于情绪（如「霓虹夜色」真的有夜色氛围）；前景/背景/强调三层分明；对比度舒适 |

## 2. typography —— 排版与可读性

| 分 | 锚点 |
|---|---|
| 1 | 文字贴边/被裁切/与背景同色不可读；字号层级混乱；HUD 大面积遮画面 |
| 3 | 可读但平庸：层级只有两档、留白无节奏、HUD 占屏略多 |
| 5 | 信息一眼可扫：字号层级 ≥3 档且各司其职；行距/字距舒服；HUD 精简且不与画面争抢 |

## 3. composition —— 构图与信息层次

| 分 | 锚点 |
|---|---|
| 1 | 无视觉焦点（不知道该看哪）；元素平均铺满；主体与背景混在一起 |
| 3 | 有主体但层次弱：背景抢戏、引导线缺失、屏幕利用不均（大片空或大片挤） |
| 5 | 第一眼落在该落的地方；前景/中景/背景或信息三级分明；留白有呼吸感 |

## 4. motion —— 动效与反馈质感（帧序列 + pack.json 观测）

机器事实（帧差/响应/冷启动曲线）是起点，视觉判断是主体。

| 分 | 锚点 |
|---|---|
| 1 | 该动的不动（操作后帧差 0）或不该动的乱闪；运动生硬跳变无过渡 |
| 3 | 有反馈但廉价：只有位移无缓动、无次级动作（squash/粒子/残影均无）；帧间明显卡顿 |
| 5 | 反馈链完整（输入→即时可感变化→余韵）；缓动自然；juice 有节奏不轰炸 |

## 5. polish —— 完成度与杂讯

| 分 | 锚点 |
|---|---|
| 1 | 明显穿帮：缺字方块、撕裂/闪烁、占位图直出、加载残留、报错痕迹可见于画面 |
| 3 | 无硬伤但糙：边缘锯齿感、元素对不齐、细部材质感缺失、UI 件风格不统一 |
| 5 | 细部经得起看：对齐精确、边缘干净、UI 件成体系、无明显「生成感」痕迹 |

## issue 书写要求

- `severity`：`major` = 用户第一眼就会注意到/影响理解；`minor` = 细节瑕疵。
- `finding` 描述**看到了什么**（现象），不是「不好」这种结论词。
- `evidence` 必须是包内文件 + 位置；一图胜千言，能引用帧序列说动效问题的不要用静态截图凑。
- `suggestion` 给**方向**不给代码；与 style card 冲突的建议不许提（卡是用户拍板的，不是你的品味）。
