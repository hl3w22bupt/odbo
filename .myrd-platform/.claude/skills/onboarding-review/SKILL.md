# 新手引导评审技能包（onboarding-review）

> 来源（mobius-design D9 / 需求 R9）：触乐《当 AI 开始重写小游戏生产流程》—— AI 帮不了的
> 4 件事里，「新手引导设计」排第二：**AI 不知道玩家为何困惑**，教训是一款游戏 90% 的测试者
> 看不懂开局。本包把这类教训前置成清单：生成引导时自查，评审引导时对照，别等玩家用脚投票。

## 0. 何时用本包

- 要给游戏写新手引导 / 开局前 60 秒体验；
- QA 互查（game-dev-qa-pair 的 qa-review 节点）要检查「新手引导是否讲清楚」；
- 人工验收前想先机器过一遍引导清单，别浪费主人的注意力。

## 1. 前置检查清单（逐条过，任何一条不满足即缺陷）

### A. 第一分钟（first minute）

- [ ] **0-10 秒**：玩家不做任何学习就能产生一次有效操作（点/按/滑），界面有且只有一个视觉焦点
- [ ] **10-30 秒**：玩家完成第一个有反馈的目标（音效/动效/数值变化三选一起码有两个），明白「我做对了」
- [ ] **30-60 秒**：玩家见到核心循环至少一次完整闭环（目标→操作→反馈→新目标）
- [ ] 前 60 秒内**零弹窗**：不做登录/公告/评分/分享弹窗打断（合规类除外）

### B. 教学方式

- [ ] 教学靠「做」不靠「读」：单条提示 ≤ 12 字、一次只教一件事、消失时机明确（操作成功后 1 秒内）
- [ ] 禁止说明书式开局长文（超过 3 行的开局文字视为缺陷，除非游戏类型本身就是文字游戏）
- [ ] 关键操作有手勢/箭头指引，指引指向的元素与可点区域一致（指向错位的引导比没有更糟）
- [ ] 跳过引导可用且状态一致（跳过后数值/解锁状态与完整引导终态相同）

### C. 失败与重试

- [ ] 第一次必然成功或必然「可恢复的失败」：不允许新手在引导期死亡且无复活/重试路径
- [ ] 引导期的失败提示说「下一步做什么」，不只说「你失败了」
- [ ] 断线/刷新/切后台回来，引导进度可恢复（至少回到当前步骤开头）

### D. 文案与本地化

- [ ] 无未解释的行话/缩写（首次出现时有一句话解释或图示）
- [ ] 引导文案与策划案 world/tone 一致（对照 `.myrd/spec/design-spec.json` 的 world 段）
- [ ] 数字与单位带上下文（「+5」是什么的 5）

## 2. 常见困惑模式（评审时按模式找证据）

| 模式 | 表现 | 判定 |
|---|---|---|
| 开局独白 | 进入游戏先看 3+ 行文字/剧情 | 缺陷：改为边玩边给 |
| 双师争宠 | 同时有两个高亮提示争夺注意力 | 缺陷：排队，一次一个 |
| 幽灵指引 | 箭头指向的区域点不出任何东西 | 缺陷：坐标错位 |
| 沉默成功 | 玩家做对了但没有任何反馈 | 缺陷：补反馈（音效/动效/数字） |
| 惩罚好奇 | 点了非引导区域就被判负/弹窗 | 缺陷：引导期屏蔽或容错 |
| 跳过断链 | 跳过引导后不知道去哪/卡死 | 缺陷：跳过也要给当前目标 |
| 数值黑箱 | 提示「升级了」但不说明变化 | 缺陷：写明变化前后 |

## 3. 评审产出（固定三行，供 QA 互查与人工拍板引用）

```
onboarding-verdict: pass | reject
onboarding-gaps: <逐条列缺陷，引用上面清单条目编号（如 A2 / B1 / 幽灵指引）>
onboarding-evidence: <截图/录屏/日志/复现步骤的落点路径>
```

## 4. 与平台机制的挂接

- 生成引导时：把本清单当 **pre-flight** 跑一遍再提交（对应 godot-game-dev 的 preflight 协议）；
- QA 互查时：qa-review 节点的「新手引导」检查项按本清单逐条核对，reject 的 feedback 引用条目编号；
- 策划案联动：引导若影响开局数值/解锁，必须回写 spec（`revise_design_spec` 或结构化修改单），
  不允许「引导里送 100 金币但 spec/数值表不知道」。
